# Grid Studio · Gate CFD 实盘网格控制台

FastAPI 后台、React + TypeScript + beUI 页面、SQLite 执行记录。页面和交易路由只使用 Gate 的真实账户及行情；旧模拟数据不会导入实盘数据库。

## Linux 一键部署

支持已安装 Docker Compose 的 Linux；Ubuntu/Debian 未安装 Docker 时会自动安装。服务器无需自行安装 Node 或 Python。程序以单个非 root 进程运行，交易数据与加密密钥保存在独立 Docker 数据卷，重启和重新构建保留原数据。

首次部署或更新，在服务器运行：

```bash
curl -fsSL https://raw.githubusercontent.com/Roco211/GATE-CFD/main/deploy/linux.sh -o /tmp/gate-cfd-install.sh && sudo bash /tmp/gate-cfd-install.sh --host 你的服务器公网IP或域名
```

安装完成后访问 `https://你的服务器公网IP或域名/`。需要放行入站 TCP 80、443；HTTP 自动跳转 HTTPS。域名须先解析到服务器。脚本使用 Caddy 和 Let's Encrypt 的短期证书配置，支持公网 IP 证书并自动续期；证书实际签发依赖服务器的公网可达性。请等待签发完成再输入 token，不要跳过证书错误。若服务器已有服务占用 80/443，请先安排独立反向代理入口，安装脚本不会停止其它服务。

只通过 SSH 加密隧道访问时，改用 `sudo bash /tmp/gate-cfd-install.sh --local`。后台只绑定 `127.0.0.1:18473`；在自己的电脑运行 `ssh -N -L 18475:127.0.0.1:18473 用户名@服务器IP` 后访问 `http://127.0.0.1:18475`。

安装目录默认 `/opt/gate-cfd`。再次运行同一命令会拉取更新、构建并替换容器；不会重置 token、Gate 密钥或策略数据库。若源码有本地修改，脚本会停止更新，保留修改。

HTTPS 安装会额外验证证书及未登录会话接口；直接使用 IP 时按浏览器不发送 SNI 的方式检查，避免容器已启动却打不开页面。验证失败会提示检查证书及入口日志，服务保留运行。

```bash
cd /opt/gate-cfd
sudo docker compose --env-file .env.deploy logs --tail=100 grid
sudo docker compose --env-file .env.deploy logs --tail=100 https
sudo docker compose --env-file .env.deploy restart grid
```

新部署不会导入本机交易密钥或旧策略。登录后在页面配置 Gate API；需要 IP 白名单时，加入服务器公网 IP。同一账户的同一策略不能由两台后台同时执行。迁移既有实盘记录应先停原后台，再复制完整数据库并重新配置服务器密钥；Windows 的加密文件不能直接在 Linux 解密。

## 首次访问验证

所有控制台页面和业务 API 都要求先验证访问 token。默认 token 已按项目所有者指定值配置，仓库仅保存 PBKDF2-SHA256 加盐哈希；前端没有 token 明文。公开入口仅包含验证页面、其静态资源与最小会话状态，不提供账户或交易数据。

验证成功后使用 HttpOnly、SameSite=Strict 会话 cookie；HTTPS 下同时启用 Secure。会话有效期 12 小时，退出验证或后台重启后需要重新验证。退出不会停止交易策略。错误验证有按来源及全局频率限制，已建立的行情连接也会在会话失效后结束。

替换默认 token：

```bash
cd /opt/gate-cfd
sudo docker compose --env-file .env.deploy exec grid python scripts/configure_access.py --path /var/lib/grid-studio/access-control.json
sudo docker compose --env-file .env.deploy restart grid
```

本地 Windows 使用 `.\.venv\Scripts\python.exe scripts/configure_access.py`，然后重启后台。脚本隐藏输入，只保存新的校验哈希。请保留 `grid_data`、`grid_keys` 数据卷的备份；不要使用 `docker compose down -v` 更新程序，这会删除持久化数据。

## Windows 打开与连接

当前机器已安装依赖。双击 **Start Grid Studio.cmd**，打开 http://127.0.0.1:18473；双击 **Stop Grid Studio.cmd** 停止后台。

1. 首先输入访问 token，验证后点击页面右上角「连接 Gate API」，填写 API Key 和 API Secret。密钥需要 CFD 账户查询及交易权限，并符合 Gate 的 IP 白名单设置。CFD 账户须已开通且状态正常。
2. 勾选「在后台加密保存」后，Windows 使用当前用户 DPAPI，Linux 使用独立受限密钥文件加密保存。重启后台可恢复连接；取消勾选则只保留在当前后台进程内存中。密钥不会回传前端、存入浏览器或写入交易数据库和日志。
3. 连接成功后读取真实余额、可用保证金、持仓及品种规格。配置区间、方向、网格数量、每格手数、循环及可选止损，点击「快速开始」创建策略。
4. 后台分批将符合当前价格条件的格位提交为 Gate 原生触发委托，同时附带相邻格位止盈和配置的止损。界面区分待提交、Gate 已挂单、待核对和撤销中；订单由 Gate 接受后才算挂单成功。连接密钥本身不会创建策略或试下订单。

也可在本地 .env 中设置 GATE_API_KEY / GATE_API_SECRET。加密保存的配置优先于环境配置；删除页面配置不会修改 .env，若其中仍有密钥，下次启动会重新读取。

## 行情的实际更新方式

当前使用官方 GET /tradfi/symbols/{symbol}/tickers，按关注品种以至少 1 秒的间隔轮询。多个页面共享后台行情缓存，通过本地 SSE 把新报价推送到浏览器。

这不是完整逐笔 tick 流：官方 CFD 文档尚未找到可确认的公开 WebSocket 行情频道，REST 的 timestamp 是服务器响应时间，不是逐笔成交序号。网络延迟、多个品种和限流会延长实际间隔，界面显示最近报价和陈旧状态。已经提交到 Gate 的触发委托及止盈止损由服务端监测，不依赖页面的报价刷新频率；补单、撤单和组合策略条件仍依赖后台及网络。实际公开响应曾返回 5 次/秒的限额，客户端有共享节流，并遵守 429 冷却时间。

K 线来自官方 1 分钟 OHLC。最新买卖报价与最近成交价可能不同。缺失的行情、账户数值或交易规格显示「—」，不生成替代数据。

## TradingView 图表

K 线区使用 TradingView Lightweight Charts 5。支持拖动平移、滚轮缩放、十字光标、最近 40/80/120 根视图及回到最新行情；图表时间显示为 UTC+8。默认按可见 K 线自动缩放价格轴，点击「适应网格」可同时查看全部已显示格位与委托价位。

「网格」显示全部 N+1 条预览线；「委托」区分当前品种的待提交格位与 Gate 实际委托，并显示委托的止盈止损；「持仓」显示真实入场价、止盈和止损。委托取消或持仓关闭后，对应线随最新账户快照移除。线只显示当前价格和状态，拖动图表不会修改实际订单。

历史数据使用 Gate 官方 1 分钟 OHLC；开市时将最新 REST 报价采样合入当前分钟，历史刷新后用官方已收盘数据校正。报价采样不代表完整逐笔成交；陈旧、闭市或缺失来源时间的报价不会延伸成新 K 线，缺失分钟不补造。新报价不会反复重置手动查看的时间范围。

采用可嵌入自有数据和价格线的 Lightweight Charts，不包含 Advanced Charts 的完整指标库、画线工具栏或拖线改单功能。

## 快速点价与智能组合

- 点击下限、上限或高级设置中的止损输入框，再点击 K 线区域或右侧价格轴，按 Gate 报价单位自动填入。点击「图表选区间」后连续选两个价格，自动排序并同时设置上下限；Esc 或提示旁的关闭按钮退出。拖动、滚轮缩放不会填价。
- 「智能组合」支持四种自动计算：区间＋手数＋目标净收益求最大可行格数；格数＋手数＋目标净收益求区间；区间＋格数＋目标净收益求手数；以及现有参数的收益试算。求区间时需选中心、下限或上限作为参考，参考价可从图表点选，留空按计算时真实买卖中间价确定。
- 每格净收益按完成一轮开仓与相邻格位止盈估算，使用 Gate 的真实合约大小、价格精度及数量限制。等差、等比都会逐格检查；报价取整后每格仍须达到目标。无法达到时显示原因，不生成看似可用的参数。
- 手续费从已连接账户的 `GET /tradfi/symbols/commissions` 读取 `fee_per_lot`，直接采用返回值，不自行叠加 VIP 折扣；官方佣金开仓收取，不再乘二。接口未提供最低每单佣金，需手动填写；确认无最低额时点击「无最低收费，填 0」。一轮佣金为每手费率乘手数与每单最低额中的较大者。
- 原生委托价本身采用买卖两侧的执行价格。「额外点差预算」是可关闭的保守预留，可取计算时 ask−bid 或手动输入；不是声称 Gate 重复收取一份点差。可另外预留往返滑点，默认显式为 0。结果展示本次采用的点差和计算时刻，行情变化后可点击重算，隔夜费未计入。
- 「应用到配置」只填写草稿，不启动策略、不改现有委托。保留原循环设置和止损，若新范围与止损冲突则拒绝应用。运行中可试算，参数锁定时不能应用。手数步长未知时结果为数学候选值，是否可委托仍由 Gate 校验。

## 延迟诊断

页面右上角点击「延迟诊断」→「一键测试延迟」。每个接口可取 3 或 5 个样本，显示成功率、P50/P95、联网、共享限流排队、校时、重试等待和本地处理耗时，并显示短暂队列探测、现有配置纯计算耗时。可停止测试并导出已有结果；关闭抽屉不会中断后台测试，重开可查看最近一次报告。

双击 `Test Latency.cmd` 可运行同一套诊断，需先启动控制台并配置账户。脚本会提示输入访问 token；无人值守执行可通过 `GRID_ACCESS_TOKEN` 环境变量提供，不要把 token 写入命令参数。命令行也可运行：

```powershell
.\.venv\Scripts\python.exe scripts/test_latency.py --symbol XAUUSD --samples 3
```

脚本自动将 Markdown 和 JSON 保存到 `data/reports`；网页提供「下载报告」和「原始 JSON」。后台最多保留最近 10 份报告，重启后清空内存报告，下载文件不受影响。网页、脚本只启动同一个共享诊断任务，不会同时叠加多组测试。

诊断只读真实行情、账户、资产、未成交委托和持仓接口，不挂测试单或撤销订单。每次最多 15/25 个逻辑读取，与现有 Gate 客户端共享节流，校时和允许的只读重试可能增加实际 HTTP 次数；单次读取最多 8 秒、整轮最多 90 秒。测试期间会使用部分请求配额，报告记录本地等待及可用的 Gate 限流响应。

联网耗时包含连接、传输和 Gate 处理，不能单独归因为网络线路。真实下单、撤单等只被动观测用户原有操作，不自动触发交易；HTTP 返回与 Gate 最终委托确认是不同环节，没有样本的项目明确标为未测得。报告中的流程预算使用当前只读样本推算，并非真实每格铺单耗时保证。小样本 P95 只描述本次测量。报告不保存 API Key、签名、余额、订单号或仓位明细。

## 网格执行规则

- N 格生成 N+1 条价格线，支持等差、等比及做多、做空。
- 做多：当前 ask 下方的格位可提交；做空：当前 bid 上方的格位可提交。不符合条件的格位保留待提交状态，报价满足条件后再挂单。每次实际发送前重新检查报价和停止信号。
- 入场调用 `POST /tradfi/orders`，使用 `price_type="trigger"`。Gate 接受后长期保留该触发委托，等待期间不会因本地的短超时重复下单。官方 CFD 接口没有单独的 limit/stop 类型选择，委托触发价不保证最终成交价。
- 已确认的独立仓位退出后，用 Gate 的仓位和平仓委托记录核对：品种、方向、时间、成交价、手数及平仓盈亏必须唯一对应，止盈触发价须与已确认保护价一致。实际成交价允许滑点；不再仅用成交价是否越过目标判断止盈。原生止盈全平后，循环模式只补回该格一次。
- 仓位已关闭但平仓委托记录尚未返回时，成交列表先显示「已平仓·原因待核对」，后台继续核对，不猜测退出原因或提前补单。普通平仓、强平、部分成交及归属歧义不会作为止盈循环恢复。
- 「恢复策略」用于核对通过的暂停策略，沿用原参数、保留已有委托和仓位，仅重新武装尚未补回的已确认止盈格位。重复点击不会重复补单；更新程序本身不会自动恢复此前暂停的策略。修改整个策略参数前需先停止当前策略。
- 「全部取消」先停止当前策略的新委托及循环补单，再逐笔撤销已确认归属的 Gate 未成交委托；已有仓位及其 Gate 原生止盈止损保留。撤单和成交可能同时发生，只有完成对账后才显示停止完成。
- 单笔「撤单」同时禁用该格的后续补单。单笔「修改委托」可调整委托价和止盈止损；持仓「修改止盈止损」调用 Gate 原生仓位接口。输入留空保留当前保护价，明确输入 0 或选择清空才移除。
- 修改委托会同步该格后续轮次的入场价和保护价；修改持仓保护只影响当前仓位，下一轮仍使用该格参数。清空止盈会禁用该格自动补单。策略配置的止损价还用于后台停止铺单及撤销剩余委托，单独修改或清空某一仓位的止损不会修改这个策略条件。
- 「撤单并平仓」是独立操作：先停止补单、撤销本策略委托，再关闭本策略可确认归属的仓位，并处理撤单时发生的成交。不会操作其他策略或人工订单；结果未知时保持待核对，不重复平仓。
- 报价过期、休市、方向限制、资金不足、部分成交或交易结果未知时不继续新开仓。成交响应未确认时保存待核对状态，不自动重复发送原交易请求。
- 杠杆由官方品种详情提供，当前 CFD API 没有可用的修改杠杆接口。手数最小/最大值按真实规格校验，官方未给出步长时不编造步长。仅美元结算品种显示保证金及毛利估算，实际保证金由 Gate 判断。
- 网页关闭后后台继续执行；停止后台后，已经挂在 Gate 的触发委托及仓位止盈止损仍有效，新的铺单、循环补单和策略级撤单不再执行。重启先恢复记录并对账，接管原有原生挂单，不重复提交。
- 升级前的本地触发策略标记为旧版策略；仍运行的旧策略会暂停，需要停止后重新创建原生策略。已有持仓和历史归属保留，不自动转换成新订单。

## 订单关联与恢复

官方下单返回队列任务 id；后台将其作为日志查询候选，并核对日志编号及下单参数后取得真实 order_id。当前仓位没有直接的 order_id 关联字段，因此还需通过真实委托状态、当前及近期历史仓位，按品种、方向、数量、成交时间及可用的成交价/TP/SL 唯一匹配 position_id。不会假设订单编号等于仓位编号。

当前真实平仓接口额外返回 `sl_tp_type`，本次核实的两笔止盈记录均为 `2`；这项枚举尚未写入公开 CFD 文档及 SDK 模型。程序只在该标识、已知 TP 触发价及双向唯一平仓证据同时满足时确认止盈，并保存关联记录。未知标识、缺失字段、截断历史或多个匹配均保留待核对，不用盈亏正负代替退出原因。

实际核查中，不带时间范围的订单历史只返回最近 10 条。后台会为本策略已平仓仓位按时间、品种和平仓方向补查，限制每轮请求数，空结果稍后重试，并持久保留已核对窗口的原始记录和已见入场订单历史。该接口按订单创建时间筛选，仓位关联使用成交完成时间；查询结果疑似截断时继续保留待核对。

运行某品种时，应由本控制台独占该品种的自动开仓；同时由其他程序或人工开出相同参数的仓位，现有 API 无法保证辨别来源。发现多条匹配、部分成交或未知写入时显示待核对，并保留记录，不猜测归属或盲目重发。请在 Gate 核对真实委托与持仓。

实盘数据默认保存在 data/live.sqlite3；凭据密文保存在 data/gate-credentials.json；Windows 密文绑定当前用户，Linux 密文依赖独立密钥卷，不能单独复制密文后直接解密。运行时不要修改或替换数据库。策略绑定 MT5 账户编号；仍有运行策略或待核对交易时，页面阻止换到另一账户或清除连接。

## 开发与验证

首次安装或迁移使用 Python 3.11+、Node.js 22+ 和 pnpm，运行 setup.ps1。脚本支持当前机器附带的运行环境。

开发后台：.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 18473 --workers 1

开发前端：pnpm dev，在 http://127.0.0.1:5173 打开。生产页面由 FastAPI 提供 dist 文件，无需同时运行前端开发服务。

验证命令：.venv\Scripts\python.exe -m pytest -q、pnpm test，以及 pnpm build。运行中的页面直接读取 dist；开发期间可用 pnpm exec vite build --outDir .validation-dist 做隔离构建，完成验证后再更新生产文件。

图表数据与挂单线测试：pnpm test:chart（Node.js 22.18+，当前环境为 24）。测试覆盖时间归一、乱序报价、休市、历史校正、订单来源区分、品种隔离和撤单后移除价格线。
